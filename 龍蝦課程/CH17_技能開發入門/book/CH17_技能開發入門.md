# CH17 | 技能開發入門

---

前面兩章你學會了安裝和使用現成的技能。但如果你想要的功能沒有人做過呢？比如你想讓龍蝦幫你管理班上學生的成績、或是自動整理某個特定網站的資訊、或是用你們學校的系統幫你請假。

這些太客製化了，不可能有現成的技能。但好消息是——自己寫一個技能比你想像的簡單得多。一個技能的核心就是一個 SKILL.md 檔案，你只要用 Markdown 把「要做什麼」寫清楚，龍蝦的 AI 大腦就會知道怎麼做。

這一章帶你從零開始寫一個技能，測試它，然後分享給別人。

> **本章學習目標**
>
> 1. 理解為什麼要自己開發技能
> 2. 熟悉 SKILL.md 的格式規範
> 3. 從零開始寫一個完整的技能
> 4. 學會測試和除錯技能
> 5. 知道怎麼發布和分享技能

---

## 17.1 為什麼要自己開發技能

### 17.1.1 現成技能的限制

ClawdHub 上有 50+ 個技能，但它們是為「通用場景」設計的。以下情境可能找不到現成的：

| 你想做的事 | 為什麼沒有現成技能 |
|-----------|-----------------|
| 管理班上學生的成績 | 太客製化，每個老師的需求不同 |
| 查詢你們公司的內部系統 | 每間公司的系統不一樣 |
| 自動整理特定論壇的文章 | 每個網站的結構不同 |
| 用特定格式產生報表 | 格式因人而異 |
| 操作你自己寫的程式 | 只有你知道怎麼操作 |

### 17.1.2 自己寫沒有想像中難

一個技能的核心其實就是：

1. **一個 SKILL.md 檔案**——告訴龍蝦這個技能是什麼、能做什麼
2. **（可選）腳本檔案**——如果需要執行程式碼

最簡單的技能甚至不需要任何程式碼——只要 SKILL.md 寫得夠清楚，龍蝦的 AI 就能照做。

---

## 17.2 SKILL.md 格式規範

### 17.2.1 基本結構

每個 SKILL.md 都有一個固定的結構：

```markdown
---
name: 技能名稱（英文，用小寫和連字號）
description: 一句話描述這個技能做什麼
---

# 技能的完整名稱

目標：用一兩句話說明這個技能的目的。

## 功能

列出這個技能能做的事情。

## 使用方式

說明使用者可能怎麼觸發這個技能（用自然語言描述）。

## 執行方式（給龍蝦看的）

詳細說明龍蝦該怎麼執行這個技能——步驟、規則、限制。

## 需要的設定（如果有的話）

列出需要什麼 API Key 或設定。
```

### 17.2.2 前置資料（Front Matter）

SKILL.md 最上面用 `---` 包起來的部分叫「前置資料」（Front Matter），它告訴 OpenClaw 這個技能的基本資訊：

```yaml
---
name: my-skill          # 技能 ID，英文小寫，用連字號分隔
description: 這是我的技能  # 一句話描述
---
```

這兩個欄位是必填的。`name` 用英文是因為它會被系統用來識別技能，`description` 可以用中文。

### 17.2.3 好的 SKILL.md 長什麼樣

**關鍵原則：寫給 AI 看，不是寫給人看。**

龍蝦的 AI 大腦會讀 SKILL.md 來理解這個技能。所以你要把「怎麼做」寫得非常清楚，就像你在教一個很聰明但完全不知道背景的新同事：

- ✅ 「查詢 OpenWeatherMap API，用 GET 請求，endpoint 是 /data/2.5/weather」
- ❌ 「去查天氣 API」（哪個 API？怎麼查？）

- ✅ 「如果使用者沒有指定城市，用 TOOLS.md 裡的預設城市」
- ❌ 「用預設值」（什麼預設值？在哪裡？）

## 17.3 實戰：從零開始寫一個技能

讓我們用一個具體的範例，一步步寫出一個完整的技能。

### 17.3.1 情境設定

假設你是一位老師，每天要記錄學生的出缺席狀況。你想讓龍蝦幫你做這件事——在 LINE 上跟龍蝦說「今天王小明請假」，龍蝦就會幫你記錄下來。

### 17.3.2 步驟一：建立技能資料夾

```powershell
mkdir C:\Users\你的名稱\.openclaw\workspace\skills\attendance
```

### 17.3.3 步驟二：撰寫 SKILL.md

在 `attendance` 資料夾裡建立 `SKILL.md`：

```markdown
---
name: attendance
description: 記錄和查詢學生出缺席狀況，支援請假、遲到、曠課的紀錄與統計。
---

# Attendance（學生出缺席管理）

目標：幫老師記錄班上學生的出缺席狀況，並能查詢統計資料。

## 功能

1. 記錄學生的出缺席（出席、請假、遲到、曠課）
2. 查詢某位學生的出缺席紀錄
3. 查詢某天的全班出缺席狀況
4. 統計一段時間內的出缺席報表

## 使用方式

使用者可能會這樣說：
- 「今天王小明請假」
- 「記錄一下，李小華遲到」
- 「張大偉這個月的出缺席紀錄」
- 「今天有誰請假？」
- 「這週的出缺席統計」

## 資料儲存

所有紀錄存在工作區的 `data/attendance/` 資料夾裡：
- 每天一個檔案：`data/attendance/2026-03-07.md`
- 格式：

```
# 2026-03-07（五）出缺席紀錄

| 學生 | 狀態 | 備註 |
|------|------|------|
| 王小明 | 請假 | 感冒 |
| 李小華 | 遲到 | 遲到 10 分鐘 |
```

## 執行方式

### 記錄出缺席
1. 從使用者的訊息中提取：學生姓名、狀態（出席/請假/遲到/曠課）、備註
2. 檢查 `data/attendance/` 資料夾是否存在，不存在就建立
3. 開啟或建立今天的檔案（以日期命名）
4. 新增一筆紀錄到表格裡
5. 回覆確認

### 查詢紀錄
1. 從使用者的訊息中判斷要查什麼（某人、某天、某段時間）
2. 讀取對應的檔案
3. 整理成易讀的格式回覆

### 統計報表
1. 讀取指定時間範圍的所有檔案
2. 統計每位學生的出席、請假、遲到、曠課次數
3. 用表格格式回覆

## 安全原則

- 不要刪除已有的紀錄，只能新增和修改
- 修改紀錄時要先跟使用者確認
- 學生的個人資料不要在群組中揭露
```

### 17.3.4 步驟三：重啟並測試

```powershell
openclaw gateway restart
```

然後在 LINE 上測試：

```
你：今天王小明請假，感冒
龍蝦：✅ 已記錄：
      📅 2026/03/07
      👤 王小明
      📋 狀態：請假
      📝 備註：感冒

你：李小華遲到了十分鐘
龍蝦：✅ 已記錄：
      📅 2026/03/07
      👤 李小華
      📋 狀態：遲到
      📝 備註：遲到 10 分鐘

你：今天有誰請假？
龍蝦：📋 今天（3/7）請假名單：
      1. 王小明（感冒）
      其他同學都有出席。
```

### 17.3.5 步驟四：微調

第一版很少完美。根據實際測試的結果，你可能需要修改 SKILL.md：

- 如果龍蝦把學生名字辨識錯了，在 SKILL.md 裡加一份學生名單
- 如果格式不是你要的，修改「資料儲存」的格式說明
- 如果龍蝦不理解某些說法，在「使用方式」裡加更多範例

每次修改 SKILL.md 後都要重啟 Gateway。

## 17.4 測試與除錯

### 17.4.1 測試的三個層次

**層次一：基本功能測試**

先確認技能的核心功能能正常運作：
- 能不能記錄資料？
- 能不能查詢資料？
- 回覆的格式對不對？

**層次二：邊界情境測試**

試試不正常的輸入，看龍蝦怎麼反應：
- 「今天請假」（沒有說是誰）
- 「王小明」（沒有說什麼事）
- 「三年前的出缺席紀錄」（資料不存在）

**層次三：長期使用測試**

用一兩週確認：
- 資料有沒有正確累積？
- 統計報表準不準確？
- 有沒有遺漏或重複的問題？

### 17.4.2 常見問題排查

| 問題 | 可能的原因 | 解決方法 |
|------|-----------|---------|
| 龍蝦不理解要用這個技能 | SKILL.md 的 description 太模糊 | 改得更具體 |
| 龍蝦不知道怎麼做 | 「執行方式」寫得不夠詳細 | 補充更多步驟細節 |
| 存檔格式不對 | 「資料儲存」的格式說明不清楚 | 給一個完整的範例 |
| 存檔位置找不到 | 路徑沒寫清楚 | 用絕對路徑或明確的相對路徑 |

### 17.4.3 用 Doctor 檢查

```powershell
openclaw doctor
```

Doctor 會檢查所有技能的 SKILL.md 是否有格式錯誤。

## 17.5 發布與分享

### 17.5.1 分享給朋友

最簡單的方式——把技能資料夾打包成 ZIP：

```powershell
# 壓縮技能資料夾
Compress-Archive -Path C:\Users\你的名稱\.openclaw\workspace\skills\attendance -DestinationPath attendance-skill.zip
```

朋友拿到後，解壓縮到他的 `skills/` 資料夾，重啟 Gateway 就能用。

### 17.5.2 發布到 ClawdHub

如果你覺得你的技能對其他人也有用，可以發布到 ClawdHub 讓全世界都能安裝：

```powershell
clawdhub publish attendance
```

系統會引導你填寫：
- 技能名稱和描述
- 作者資訊
- 版本號
- 分類標籤

發布後，其他人就能用 `clawdhub install attendance` 安裝你的技能了。

### 17.5.3 放到 GitHub

你也可以把技能放到 GitHub 上：

1. 建立一個 GitHub Repository
2. 把技能資料夾的內容推上去
3. 在 README 裡寫安裝說明

其他人可以手動下載，或用 `clawdhub install github:你的帳號/你的Repo` 安裝。

## 17.6 常見問題

**Q1：我完全不會寫程式，可以開發技能嗎？**

可以！最簡單的技能只需要一個 SKILL.md 文字檔，不需要任何程式碼。你只要用自然語言把「要做什麼」寫清楚就好。龍蝦的 AI 大腦會理解你的指示。本章的出缺席管理範例就是這種純文字技能。

**Q2：什麼時候需要寫程式碼？**

當你的技能需要呼叫外部 API 或執行複雜的資料處理時，可能需要搭配腳本（JavaScript 或 PowerShell）。但對大部分的自用技能來說，純 SKILL.md 就夠了。

**Q3：SKILL.md 寫得越詳細越好嗎？**

大部分情況是的——越詳細龍蝦越知道該怎麼做。但有個上限：太長的 SKILL.md 會佔用 AI 的上下文空間。建議控制在 100 行以內。如果技能很複雜，可以拆成多個互相搭配的技能。

**Q4：我修改了 SKILL.md 但龍蝦的行為沒變**

每次修改 SKILL.md 都要重啟 Gateway：`openclaw gateway restart`。另外，如果龍蝦之前用舊的方式做過，它的短期記憶可能還記得舊方式——開一段新對話再試試。

**Q5：可以用 ChatGPT 或 Claude 幫我寫 SKILL.md 嗎？**

當然可以！把你想要的功能描述給 AI，請它幫你寫 SKILL.md。它們很擅長這種結構化的文件撰寫。你拿到初版後再根據實測結果微調。

這一章帶你跨過了從「使用者」到「開發者」的門檻：

- **SKILL.md 格式**——前置資料 + 功能描述 + 使用方式 + 執行方式
- **從零建立技能**——用出缺席管理的完整範例走過全流程
- **測試與除錯**——三個層次的測試 + 常見問題排查表

自己寫技能的最大好處是：**你的龍蝦可以做到任何你想得到的事**。不再受限於別人做了什麼技能。
