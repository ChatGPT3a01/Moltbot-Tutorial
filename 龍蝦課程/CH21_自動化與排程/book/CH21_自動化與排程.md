## 21.1 HEARTBEAT.md 深入教學

### 21.1.1 完整語法回顧

在 CH16 我們學過 HEARTBEAT.md 的基本格式。現在來看完整的語法：

```markdown
# HEARTBEAT.md

## 任務名稱
- 排程: <cron 表達式 或 自然語言>
- 通道: <要推播到哪個通道>
- 對象: <推播給誰（用戶 ID 或群組 ID）>
- 動作: <要做什麼>
- 條件: <（可選）什麼情況下才執行>
- 靜默: <（可選）true/false，不回報執行結果>
```

### 21.1.2 排程表達式

排程有兩種寫法——Cron 表達式和自然語言：

**Cron 表達式**

```
分 時 日 月 星期
```

| 範例 | 意思 |
|------|------|
| `0 8 * * *` | 每天早上 8:00 |
| `30 12 * * 1-5` | 平日中午 12:30 |
| `0 9 * * 1` | 每週一早上 9:00 |
| `0 0 1 * *` | 每月 1 號凌晨 0:00 |
| `*/30 * * * *` | 每 30 分鐘 |
| `0 8,12,18 * * *` | 每天 8:00、12:00、18:00 |

如果你不熟悉 Cron 語法，沒關係——OpenClaw 也支援自然語言：

**自然語言**

| 範例 | 意思 |
|------|------|
| `每天 08:00` | 每天早上 8:00 |
| `每小時` | 每小時整點 |
| `平日 09:00` | 週一到週五早上 9:00 |
| `每週一 10:00` | 每週一早上 10:00 |
| `每月 1 號 09:00` | 每月 1 號早上 9:00 |
| `每 30 分鐘` | 每 30 分鐘一次 |

OpenClaw 會自動把自然語言轉成 Cron 表達式。

### 21.1.3 通道與對象

你可以指定任務結果推播到哪個通道、給誰看：

```markdown
## 每日天氣（推送到 LINE）
- 排程: 每天 07:30
- 通道: line
- 對象: U1234567890abcdef（你的 LINE User ID）
- 動作: 查詢今天的天氣並推播

## 群組早安（推送到 LINE 群組）
- 排程: 每天 08:00
- 通道: line
- 對象: C1234567890abcdef（群組 ID）
- 動作: 傳送早安問候和今日重點新聞

## Discord 每日報告
- 排程: 每天 18:00
- 通道: discord
- 對象: #general（頻道名稱）
- 動作: 傳送今日工作摘要
```

如果不指定通道和對象，龍蝦會在執行完任務後，等你下次傳訊息時主動回報。

### 21.1.4 條件執行

有些任務不需要每次都執行——可以加上條件：

```markdown
## 下雨提醒
- 排程: 每天 06:30
- 通道: line
- 條件: 今天有降雨機率 > 50%
- 動作: 提醒帶傘，並告知降雨時段

## 股票警報
- 排程: 每 30 分鐘（平日 09:00-13:30）
- 通道: line
- 條件: 台積電股價跌破 800 或漲破 900
- 動作: 推播股價變動通知

## 低溫警報
- 排程: 每天 20:00
- 通道: line
- 條件: 明天最低溫 < 15°C
- 動作: 提醒明天很冷，建議穿著
```

龍蝦會先檢查條件是否成立，條件成立才執行動作。這樣就不會收到一堆不需要的通知。

## 21.2 定時任務實戰

### 21.2.1 完整的每日報告

把多個排程組合在一起，龍蝦就變成你的每日 AI 秘書：

```markdown
# HEARTBEAT.md — 全自動 AI 秘書

## 早安報告
- 排程: 每天 07:30
- 通道: line
- 動作: |
    產生今日早安報告，包含：
    1. 今天的天氣和穿衣建議
    2. 今天的行事曆行程（查 Google Calendar）
    3. 今日重點新聞摘要（3 則）
    4. 一句勵志小語
    用溫暖的語氣說早安。

## 午間提醒
- 排程: 平日 12:00
- 通道: line
- 動作: |
    提醒下午的行程，
    並根據天氣建議是否適合外出午餐。

## 下班摘要
- 排程: 平日 18:00
- 通道: line
- 動作: |
    整理今天的工作摘要：
    1. 今天完成了什麼（查待辦清單）
    2. 還有什麼未完成
    3. 明天的行程預覽

## 睡前新聞
- 排程: 每天 22:00
- 通道: line
- 動作: |
    推播今日重點新聞（5 則），
    用輕鬆的語氣說晚安。
```

### 21.2.2 每週/每月任務

```markdown
## 週報整理
- 排程: 每週五 17:00
- 通道: line
- 動作: |
    整理這週的重點回顧：
    1. 本週完成的待辦事項
    2. 本週的天氣統計
    3. 本週的重大新聞回顧
    用條列式整理。

## 月度回顧
- 排程: 每月最後一天 20:00
- 通道: line
- 動作: |
    產生本月回顧報告：
    1. 行事曆統計（開了幾次會、有什麼重要活動）
    2. 出缺席統計（如果有用 attendance 技能）
    3. 下個月的重要日期預覽

## 生日提醒
- 排程: 每天 08:00
- 條件: 今天是某位朋友的生日（查 USER.md 裡的生日清單）
- 通道: line
- 動作: 提醒今天是誰的生日，建議傳個祝福訊息
```

### 21.2.3 系統維護任務

```markdown
## 磁碟空間檢查
- 排程: 每週日 03:00
- 靜默: true
- 動作: |
    檢查 C: 和 D: 的剩餘空間。
    如果任一磁碟剩餘空間 < 10GB，推播通知。
    否則不用回報。

## 備份提醒
- 排程: 每月 1 號 09:00
- 通道: line
- 動作: 提醒進行每月資料備份，列出建議備份的項目

## 龍蝦健康檢查
- 排程: 每天 04:00
- 靜默: true
- 動作: |
    執行 openclaw doctor 自我檢查。
    如果有任何異常，推播到 LINE 通知。
    正常的話不用回報。
```

## 21.3 事件驅動自動化

### 21.3.1 什麼是事件驅動

排程任務是「定時做事」——每天幾點幾分執行。但有些自動化需要「有事情發生時」才觸發。

| 類型 | 排程（定時） | 事件驅動 |
|------|------------|---------|
| 觸發方式 | 固定時間 | 特定事件發生時 |
| 範例 | 每天 8 點報天氣 | 收到 Email 時自動摘要 |
| 比喻 | 鬧鐘 | 門鈴 |

### 21.3.2 OpenClaw 支援的事件

OpenClaw 可以監聽多種事件，在事件發生時自動執行動作：

| 事件 | 觸發條件 | 範例用途 |
|------|---------|---------|
| **email-received** | 收到新 Email | 自動摘要重要信件 |
| **calendar-event** | 行事曆事件即將開始 | 提前 15 分鐘提醒 |
| **file-changed** | 特定資料夾有新檔案 | 自動處理下載的檔案 |
| **webhook-received** | 收到外部 Webhook | GitHub Issue、Stripe 付款等 |
| **keyword-detected** | 使用者訊息包含特定關鍵字 | 特殊指令觸發 |
| **price-alert** | 股價或匯率觸發條件 | 投資警報 |

### 21.3.3 在 HEARTBEAT.md 裡設定事件驅動

```markdown
## Email 自動摘要
- 事件: email-received
- 條件: 寄件者是老闆（boss@company.com）
- 動作: |
    自動讀取信件內容，產生摘要，
    並推播到 LINE 告訴我：
    「老闆寄了一封信：[摘要]，需要回覆嗎？」

## 行程提前提醒
- 事件: calendar-event
- 條件: 事件開始前 15 分鐘
- 通道: line
- 動作: |
    推播提醒：
    「15 分鐘後有行程：[事件名稱]，在 [地點]。」
    如果有 Google Maps 連結就附上。

## 下載資料夾自動整理
- 事件: file-changed
- 條件: ~/Downloads/ 有新檔案
- 靜默: true
- 動作: |
    檢查新下載的檔案類型：
    - PDF → 移到 文件/PDF/
    - 圖片 → 移到 圖片/下載/
    - ZIP → 移到 壓縮檔/
    每次整理後在日誌裡記錄。

## GitHub Issue 自動回覆
- 事件: webhook-received
- 條件: 來源是 GitHub，事件類型是 issues.opened
- 動作: |
    讀取 Issue 標題和內容，
    自動判斷是 bug 還是 feature request，
    回覆一個友善的初始回覆（感謝回報 + 預計處理時間）。
```

## 21.4 實戰：打造全自動 AI 助手

### 21.4.1 情境設定

讓我們用一個完整的範例，展示全自動龍蝦的威力。假設你是一位老師兼小型 YouTube 頻道經營者：

**你的需求：**
- 每天自動收到天氣和行程提醒
- 學生出缺席紀錄要自動統計
- YouTube 頻道有新留言時通知你
- 重要 Email 自動摘要
- 每週產生一份週報

### 21.4.2 完整的 HEARTBEAT.md

```markdown
# HEARTBEAT.md — 老師版全自動龍蝦

---

## 一、每日例行

### 早安報告
- 排程: 平日 06:45
- 通道: line
- 動作: |
    早安報告：
    1. 今天天氣和穿衣建議
    2. 今天的課表（查 Google Calendar）
    3. 今天有哪些學生請假（查出缺席紀錄）
    4. 一句教學金句

### 課前提醒
- 排程: 平日 07:45
- 通道: line
- 動作: |
    第一堂課開始前提醒：
    今天第一堂是什麼課、在哪間教室、要帶什麼教材。

### 放學摘要
- 排程: 平日 16:30
- 通道: line
- 動作: |
    今日教學摘要：
    1. 今天上了哪些課
    2. 出缺席統計
    3. 明天的課表預覽
    4. 有沒有待批改的作業

---

## 二、條件觸發

### 下雨提醒
- 排程: 平日 06:30
- 條件: 今天降雨機率 > 60%
- 通道: line
- 動作: 提醒帶傘，並建議學生帶雨具

### 冷氣團警報
- 排程: 每天 20:00
- 條件: 明天最低溫 < 12°C
- 通道: line
- 動作: 提醒明天超冷，建議穿什麼

## 三、事件驅動

### 重要 Email
- 事件: email-received
- 條件: 寄件者包含「教育局」或「校長」
- 通道: line
- 動作: 自動摘要信件內容，推播到 LINE

### YouTube 新留言
- 事件: webhook-received
- 條件: 來源是 YouTube，有新留言
- 靜默: false
- 動作: |
    讀取留言內容，分類：
    - 問題類 → 推播提醒我回覆
    - 讚美類 → 記錄下來，週報時統計
    - 垃圾留言 → 標記待刪除

## 四、週期任務

### 週報
- 排程: 每週五 17:00
- 通道: line
- 動作: |
    本週教學週報：
    1. 本週上課時數
    2. 全班出缺席統計
    3. YouTube 頻道本週表現（觀看數、新留言）
```

## 21.5 自動化的注意事項

### 21.5.1 不要過度自動化

自動化很爽，但太多通知會變成干擾。建議：

| 原則 | 說明 |
|------|------|
| **合併通知** | 把同一時段的多個通知合併成一則 |
| **善用條件** | 加條件過濾，不要每次都推播 |
| **善用靜默** | 背景任務用靜默模式，有異常才通知 |
| **分級重要性** | 重要的即時推播，不重要的收到週報裡 |

### 21.5.2 費用考量

自動化任務會消耗 AI API 的額度：

| 任務 | 預估每次消耗 | 每月成本估算 |
|------|------------|------------|
| 天氣查詢 | ~500 tokens | 每天 1 次 ≈ $0.5/月 |
| 新聞摘要 | ~2000 tokens | 每天 1 次 ≈ $2/月 |
| Email 摘要 | ~1000 tokens/封 | 看 Email 量 |
| 週報 | ~3000 tokens | 每月 4 次 ≈ $0.5/月 |

用 Gemini 3 Flash 的話，以上所有加起來每月大約 $3-5 美元（約 100-150 台幣）。如果用 Ollama 本地模型則完全免費（但需要好的電腦硬體）。

### 21.5.3 錯誤處理

自動化任務有時候會失敗——API 不通、網路斷線等。龍蝦會怎麼處理？

```markdown
## 自動化錯誤處理（在 AGENTS.md 裡設定）

### 排程任務失敗時
1. 自動重試一次（間隔 5 分鐘）
2. 如果重試也失敗，推播通知告訴使用者
3. 在日誌裡記錄錯誤原因
4. 不要無限重試（最多重試 3 次）
```

## 21.6 常見問題

**Q1：HEARTBEAT.md 可以寫多少個任務？**

沒有硬性限制，但建議控制在 15 個以內。太多任務會增加龍蝦的負擔（每次啟動都要載入所有排程），也增加 API 費用。

**Q2：定時任務的時間準確嗎？**

大致準確，但可能有 1-2 分鐘的誤差。OpenClaw 不是精密的排程系統（不像 Linux 的 cron 那麼精準），但對「早安報告」這類任務來說，差一兩分鐘完全沒差。

**Q3：電腦關機了排程還會執行嗎？**

不會。如果你的電腦關機，Gateway 沒在跑，排程不會執行。這就是為什麼 CH19 教你用 Nodes 把主控放在雲端——雲端 24 小時在線，排程就不會漏掉。

**Q4：事件驅動需要額外設定嗎？**

要。每種事件的觸發來源不同，例如：
- Email 事件需要設定好 Email 技能（CH16）
- Calendar 事件需要設定 Google Calendar API
- Webhook 事件需要在外部服務設定 Webhook 指向 OpenClaw
- 檔案事件需要 Desktop Agent（CH18）的檔案監控功能

**Q5：自動化任務可以測試嗎？**

可以。用 CLI 手動觸發排程任務來測試：

```powershell
openclaw heartbeat run "早安報告"    # 手動執行指定任務
openclaw heartbeat test              # 測試所有任務（不真的推播）
```
