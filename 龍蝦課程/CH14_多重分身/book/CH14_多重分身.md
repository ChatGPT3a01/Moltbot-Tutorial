# CH14 | 多重分身

---

到目前為止，你一直在跟「一隻」龍蝦互動。不管是 LINE、Telegram 還是 Discord，背後都是同一隻龍蝦、同一個人設、同一套記憶。這就像你只有一個助理，所有事情都找他——買菜找他、寫報告也找他、健身計畫也找他。他什麼都會一點，但什麼都不精。

如果你能有**多隻龍蝦**呢？一隻專門幫你處理工作、一隻專門陪你學英文、一隻專門管你的健康——每隻都有自己的名字、個性和專長。就像公司裡有不同部門的員工，各司其職。

這一章要教你怎麼做到這件事。

> **本章學習目標**
>
> 1. 理解「一隻龍蝦守多通道」和「多隻龍蝦」的差別
> 2. 學會設定多個 OpenClaw 實例
> 3. 了解跨頻道記憶與訊息路由的運作方式
> 4. 實戰建立一個「雙龍蝦」系統

---

## 14.1 一隻龍蝦守多個頻道

### 14.1.1 目前的架構

回顧一下你到目前為止的設定。你有一隻龍蝦，它可能同時連接了：

```
LINE ──────┐
           │
Telegram ──┼── 龍蝦（一個 Gateway、一套人設、一個 AI 大腦）
           │
Discord ───┘
```

所有通道的訊息都送到同一隻龍蝦。它用同一份 IDENTITY.md 的人設回覆所有人。如果你在 IDENTITY.md 裡寫「我是小蝦，你的學習夥伴」，那不管是 LINE 上的媽媽還是 Discord 上的同事問它，它都會自稱「小蝦，你的學習夥伴」。

### 14.1.2 這樣有什麼問題

對很多人來說，一隻龍蝦就夠了。但以下情境可能會讓你覺得不夠用：

| 情境 | 問題 |
|------|------|
| 你想在工作群組裡用龍蝦，但它的語氣太輕鬆 | 一套人設無法同時正式又輕鬆 |
| 你想給家人用，但不想讓家人看到你的工作記憶 | 一套記憶沒辦法分人顯示 |
| 你想用不同的 AI 模型處理不同的事 | 一隻龍蝦只能設定一個 AI 模型 |
| 你想讓英文助手用英文、中文助手用中文 | 一份 IDENTITY.md 只能設定一種語言 |

這時候，你就需要「多重分身」——同時跑多隻龍蝦，每隻有獨立的設定。

## 14.2 多隻龍蝦各司其職

### 14.2.1 多重分身的概念

多重分身的概念很直覺：你在電腦上跑**多個 OpenClaw Gateway**，每個 Gateway 有自己的：

- **設定檔**（不同的 `openclaw.json`）
- **工作區**（不同的 IDENTITY.md、SOUL.md 等）
- **通道連線**（不同的 LINE Bot、不同的 Telegram Bot）
- **AI 模型**（可以用不同的模型）
- **埠號**（每個 Gateway 用不同的 port）

```
LINE Bot A ─── Gateway A（port 18789）─── 工作秘書人設
                                          AI: GPT-5.2

LINE Bot B ─── Gateway B（port 18790）─── 學習夥伴人設
                                          AI: Gemini 3 Flash

Telegram ──── Gateway C（port 18791）─── 英文教師人設
                                          AI: Claude Sonnet 4.6
```

每隻龍蝦是完全獨立的，互不干擾。

### 14.2.2 你需要什麼

要跑多隻龍蝦，你需要：

1. **多個 LINE Bot**（如果你想讓不同龍蝦住在不同的 LINE Bot）——回到 LINE Developers Console 多建幾個 Messaging API Channel
2. **多個工作區資料夾**——每隻龍蝦有自己的一套設定檔
3. **不同的埠號**——每個 Gateway 用不同的 port
4. **足夠的電腦資源**——每隻龍蝦會佔用一些記憶體（通常不多，每隻約 100-200MB）

### 14.2.3 設定多個工作區

OpenClaw 支援用 `--workspace` 參數指定不同的工作區：

**建立第二隻龍蝦的工作區：**

```powershell
# 建立新的工作區資料夾
mkdir C:\Users\你的名稱\.openclaw\workspace-work
```

在新資料夾裡建立一套新的設定檔（IDENTITY.md、SOUL.md、USER.md 等）。例如「工作秘書」版本：

```powershell
# 複製預設工作區的檔案當範本
Copy-Item C:\Users\你的名稱\.openclaw\workspace\* C:\Users\你的名稱\.openclaw\workspace-work\ -Recurse
```

然後修改 `workspace-work` 裡的 IDENTITY.md，改成工作秘書的人設。

### 14.2.4 設定多個設定檔

每隻龍蝦需要自己的 `openclaw.json`：

```powershell
# 複製一份設定檔
Copy-Item C:\Users\你的名稱\.openclaw\openclaw.json C:\Users\你的名稱\.openclaw\openclaw-work.json
```

修改 `openclaw-work.json`，改以下內容：

- **Gateway 埠號**——改成 `18790`（不能跟第一隻一樣）
- **LINE Channel 資訊**——換成第二個 LINE Bot 的 Channel ID、Secret、Token
- **AI 模型**——可以用不同的模型
- **工作區路徑**——指向 `workspace-work`

### 14.2.5 啟動多隻龍蝦

```powershell
# 第一隻（預設）
openclaw gateway start

# 第二隻（指定設定檔）
openclaw gateway start --config C:\Users\你的名稱\.openclaw\openclaw-work.json
```

兩隻龍蝦會分別在不同的埠號上運行。如果你用 Cloudflare Tunnel（CH12），需要為每隻龍蝦設定不同的子域名。

## 14.3 跨頻道記憶與訊息路由

### 14.3.1 多隻龍蝦之間的記憶

每隻龍蝦有自己的工作區，所以它們的記憶是**完全獨立的**。你跟工作秘書龍蝦說的話，學習夥伴龍蝦不會知道。

這通常是你想要的結果——工作和生活分開。但如果你想讓多隻龍蝦共享某些資訊，可以：

1. **共用 USER.md**——讓多隻龍蝦都知道你是誰。用符號連結（symlink）讓多個工作區的 USER.md 指向同一個檔案
2. **共用 MEMORY.md**——讓多隻龍蝦共享長期記憶（要小心隱私問題）
3. **各自獨立**——最安全的做法，完全不共享

**建立符號連結（Windows）：**

```powershell
# 讓第二隻龍蝦的 USER.md 指向第一隻的
New-Item -ItemType SymbolicLink -Path "C:\Users\你的名稱\.openclaw\workspace-work\USER.md" -Target "C:\Users\你的名稱\.openclaw\workspace\USER.md" -Force
```

### 14.3.2 訊息路由

訊息路由很簡單——每個通道連到哪隻龍蝦，訊息就去哪。

如果你讓 LINE Bot A 連到 Gateway A、LINE Bot B 連到 Gateway B，使用者傳訊息給 Bot A 就是跟龍蝦 A 聊天，傳給 Bot B 就是跟龍蝦 B 聊天。使用者感知不到背後有多隻龍蝦——他們只是在跟不同的 Bot 聊天。

### 14.3.3 同一個通道切換龍蝦

你可能會想：「我只有一個 LINE Bot，但想在不同情境切換人設。」

這可以透過**指令切換**來實現。在龍蝦的技能裡設定：

```
你：切換到工作模式
龍蝦：好的，我現在切換到工作秘書模式。有什麼需要幫忙的？
```

這不是真的切換到另一隻龍蝦，而是在同一隻龍蝦裡切換不同的行為風格。做法是在 IDENTITY.md 裡定義多種「模式」：

```markdown
## 模式

### 日常模式（預設）
- 語氣輕鬆、像朋友聊天
- 可以開玩笑

### 工作模式
- 語氣正式、有條理
- 回覆注重效率

### 學習模式
- 有耐心、循序漸進
- 會出小測驗

當使用者說「切換到 XX 模式」，就切換到對應的風格。
```

這比跑多隻龍蝦簡單得多，適合「不想搞太複雜但想有不同風格」的使用者。

## 14.4 實戰：建立雙龍蝦系統

讓我們用一個具體的範例，走過建立雙龍蝦的完整流程。

### 14.4.1 情境設定

你想要兩隻龍蝦：

| | 龍蝦 A：小蝦（生活助手） | 龍蝦 B：龍蝦秘書（工作助手） |
|---|------------------------|--------------------------|
| **通道** | LINE Bot A | LINE Bot B |
| **人設** | 輕鬆、幽默、愛聊天 | 專業、有條理、效率導向 |
| **AI 模型** | Gemini 3 Flash（免費、快） | GPT-5.2（高品質） |
| **埠號** | 18789 | 18790 |
| **用途** | 查天氣、找餐廳、聊天 | 寫報告、整理資料、行程管理 |

### 14.4.2 步驟一：建立第二個 LINE Bot

到 LINE Developers Console，在同一個 Provider 下建立新的 Messaging API Channel。取得新的 Channel ID、Channel Secret 和 Channel Access Token。

### 14.4.3 步驟二：建立工作區和設定檔

```powershell
# 建立工作區
mkdir C:\Users\你的名稱\.openclaw\workspace-work

# 複製範本
Copy-Item C:\Users\你的名稱\.openclaw\workspace\* C:\Users\你的名稱\.openclaw\workspace-work\ -Recurse

# 複製設定檔
Copy-Item C:\Users\你的名稱\.openclaw\openclaw.json C:\Users\你的名稱\.openclaw\openclaw-work.json
```

### 14.4.4 步驟三：修改設定

修改 `workspace-work\IDENTITY.md` 為工作秘書人設（參考 CH10 的範例）。

修改 `openclaw-work.json`：
- 埠號改成 `18790`
- LINE Channel 資訊改成新 Bot 的
- AI 模型改成 `gpt-5.2`
- 工作區路徑指向 `workspace-work`

### 14.4.5 步驟四：設定 ngrok 或 Cloudflare

如果用 Cloudflare Tunnel，在 `config.yml` 裡加入第二條路由：

```yaml
ingress:
  - hostname: bot.mylobster.xyz
    service: http://localhost:18789
  - hostname: work.mylobster.xyz
    service: http://localhost:18790
  - service: http_status:404
```

記得執行 DNS 路由設定：

```powershell
cloudflared tunnel route dns lobster work.mylobster.xyz
```

然後到 LINE Developers Console，把第二個 Bot 的 Webhook URL 設成：

```
https://work.mylobster.xyz/line/webhook
```

### 14.4.6 步驟五：啟動並測試

```powershell
# 啟動兩隻龍蝦
openclaw gateway start
openclaw gateway start --config C:\Users\你的名稱\.openclaw\openclaw-work.json
```

分別在兩個 LINE Bot 上傳「你是誰？」，確認它們的回覆符合各自的人設。

## 14.5 常見問題

**Q1：跑多隻龍蝦會很吃電腦資源嗎？**

不太會。每隻龍蝦的 Gateway 大約佔 100-200MB 記憶體。如果你的電腦有 8GB 以上的 RAM，同時跑 2-3 隻完全沒問題。真正消耗資源的是 AI 模型的 API 呼叫，而那是在雲端處理的（除非你用 Ollama 本地模型）。

**Q2：多隻龍蝦可以共用同一個 AI API Key 嗎？**

可以。API Key 是跟 AI 服務商的帳號綁定的，不是跟龍蝦綁定的。多隻龍蝦用同一個 Key 完全沒問題，費用會合併計算在同一個帳號下。

**Q3：我只有一個 LINE Bot，可以跑多隻龍蝦嗎？**

一個 LINE Bot 只能連一個 Webhook URL，所以只能連到一隻龍蝦。如果你想用多隻龍蝦，就需要多個 LINE Bot。不過你可以用 14.3.3 教的「模式切換」在同一隻龍蝦裡切換風格。

**Q4：多隻龍蝦的配對是獨立的嗎？**

是的。每隻龍蝦有自己的配對系統。如果你在兩個 LINE Bot 上都想使用，兩邊都需要各自完成配對。

**Q5：有更簡單的方式嗎？我不想搞這麼複雜。**

有。14.3.3 教的「模式切換」不需要跑多隻龍蝦，只要在 IDENTITY.md 裡定義不同模式就好。這對大部分人來說已經夠用了。多重分身適合真的需要「完全獨立的龍蝦」的進階用戶。

## 14.6 小結與展望

這一章教了你龍蝦的多重分身能力：

- **一隻龍蝦守多通道**——最簡單，適合大部分人
- **模式切換**——在同一隻龍蝦裡切換不同風格，中等複雜度
- **多隻龍蝦各司其職**——完全獨立的設定、記憶和通道，最靈活

你也走過了一個完整的「雙龍蝦」建立範例，知道怎麼設定多個工作區、多個設定檔、多條 Cloudflare 路由。

至此，第四篇「通道篇」結束了。你的龍蝦可以住在各種平台上（CH13）、有正式的網址（CH12）、有漂亮的介面（CH11），甚至可以有多重分身（本章）。

接下來進入第五篇「技能篇」。龍蝦目前的能力主要靠 AI 模型本身——但 OpenClaw 有一個強大的 **Skills（技能）系統**，可以讓龍蝦學會各種新本領。在下一章 CH15，我們要認識這個技能生態系，看看龍蝦還能變得多強。
