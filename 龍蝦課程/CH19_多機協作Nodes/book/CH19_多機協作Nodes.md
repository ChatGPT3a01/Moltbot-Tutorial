# CH19 | 多機協作（Nodes）

---

你的龍蝦現在已經很厲害了——能聊天、查天氣、管行程、操作瀏覽器、整理檔案。但目前為止，龍蝦只住在「一台電腦」上。

如果你是這樣的情況呢？

- 家裡有一台桌機，辦公室有一台筆電，你想讓龍蝦同時管理兩台
- 你有一台雲端伺服器跑 24 小時，但你也想在自己的電腦上讓龍蝦做事
- 你和朋友各自有龍蝦，想讓兩隻龍蝦互相溝通、分工合作
- 你想把 AI 運算交給效能好的機器，讓小筆電只負責接收訊息

這就是 OpenClaw 的 **Nodes（多機協作）** 功能——讓多台機器上的龍蝦組成一個網路，互相合作。

> **本章學習目標**
>
> 1. 認識 Nodes 多機架構的概念
> 2. 了解主控節點與工作節點的角色
> 3. 學會設定多台龍蝦分工合作
> 4. 認識實際的應用場景

## 19.1 Nodes 多機架構介紹

### 19.1.1 什麼是 Nodes

在 OpenClaw 裡，每一台跑著 Gateway 的電腦就是一個 **Node（節點）**。到目前為止，你的系統只有一個節點——就是你自己的電腦。

Nodes 功能讓你把多個節點串在一起，形成一個「龍蝦網路」。這些節點可以在不同的地方——你的家、辦公室、雲端伺服器——只要能連上網路，就能協作。

### 19.1.2 為什麼需要多節點

| 情境 | 單機的限制 | 多節點的解法 |
|------|-----------|------------|
| 電腦關機就斷線 | 龍蝦下線，無法接收訊息 | 雲端節點 24 小時接收，本機節點負責重工作 |
| 多台電腦要管理 | 每台各自裝龍蝦，互不相干 | 多節點串聯，統一管理 |
| 運算效能不夠 | 小筆電跑 AI 很慢 | 把 AI 運算丟給效能好的節點 |
| 多人協作 | 每人各自操作 | 龍蝦之間可以互相傳遞任務 |

### 19.1.3 節點的角色

在 Nodes 架構裡，節點分為兩種角色：

| 角色 | 說明 | 比喻 |
|------|------|------|
| **Primary（主控節點）** | 接收所有訊息、分派任務、管理全局 | 公司的總經理 |
| **Worker（工作節點）** | 接收主控分派的任務，執行後回報結果 | 各部門的員工 |

一個 Nodes 網路裡只有一個 Primary，但可以有多個 Worker。

### 19.1.4 架構圖

```
            ┌─────────────┐
            │   LINE 訊息   │
            └──────┬──────┘
                   │
            ┌──────▼──────┐
            │   Primary    │  ← 主控節點（雲端伺服器）
            │  接收訊息     │     24 小時在線
            │  分派任務     │
            └──┬───────┬──┘
               │       │
        ┌──────▼──┐ ┌──▼──────┐
        │ Worker A │ │ Worker B │
        │ 家裡桌機  │ │ 辦公室筆電│
        │ 跑 AI 運算│ │ 操作檔案  │
        └─────────┘ └─────────┘
```

## 19.2 主控節點與工作節點

### 19.2.1 主控節點（Primary）

主控節點是整個網路的「大腦」。它負責：

1. **接收所有通道的訊息**——LINE、Telegram、Discord 等所有訊息都先到主控
2. **判斷任務要交給誰**——根據任務類型和各節點的能力，分派工作
3. **彙整結果回覆使用者**——工作節點完成後，主控節點負責把結果傳回給你
4. **維持節點清單**——知道有哪些工作節點在線上

主控節點通常放在**雲端伺服器**或**24 小時開機的電腦**上，確保隨時能接收訊息。

### 19.2.2 工作節點（Worker）

工作節點是「執行者」。它負責：

1. **向主控註冊**——告訴主控「我上線了，我能做什麼」
2. **接收任務**——等待主控分派任務
3. **執行任務**——可能是跑 AI、操作檔案、執行腳本等
4. **回報結果**——完成後把結果送回主控

工作節點可以是你的**家用電腦、辦公室筆電、或另一台雲端伺服器**。

### 19.2.3 節點能力標籤

每個工作節點可以宣告自己的「能力」，讓主控知道該把什麼任務分派給它：

```markdown
# NODE.md（工作節點的設定檔）

## 節點名稱
家裡桌機

## 能力
- desktop-agent（可操控瀏覽器和檔案）
- gpu-compute（有好顯卡，可跑本地 AI）
- file-access（可存取家裡的 NAS）

## 在線時段
- 平日：18:00-23:00
- 假日：全天
```

主控節點看到這個設定，就知道：
- 如果要操控桌面 → 分給「家裡桌機」
- 如果要跑本地 AI → 分給「家裡桌機」（因為有 GPU）
- 如果是凌晨的任務 → 不分給「家裡桌機」（可能關機了）

## 19.3 多台龍蝦分工合作設定

### 19.3.1 前置準備

在設定 Nodes 之前，你需要準備：

| 項目 | 說明 |
|------|------|
| 至少兩台電腦 | 一台當 Primary，一台當 Worker |
| 每台都裝好 OpenClaw | 確認 `openclaw doctor` 通過 |
| 網路能互通 | 同一區網，或都有公網/Tunnel |
| Cloudflare Tunnel（推薦） | 讓不在同一區網的節點能互相連線 |

### 19.3.2 步驟一：設定主控節點

在你打算當主控的機器上：

```powershell
# 啟用 Nodes 功能
openclaw config set nodes.enabled true

# 設定自己為 Primary
openclaw config set nodes.role primary

# 產生節點金鑰（讓其他節點能安全連線）
openclaw nodes init
```

執行 `openclaw nodes init` 後會產生一組金鑰：

```
🔑 Nodes 初始化完成！
   節點 ID：node-abc123
   連線金鑰：sk-nodes-xxxxxxxxxxxxxxxx

   ⚠️ 請把連線金鑰複製給你的工作節點。
   這個金鑰只顯示一次，請妥善保管。
```

### 19.3.3 步驟二：設定工作節點

在你要當工作節點的機器上：

```powershell
# 啟用 Nodes 功能
openclaw config set nodes.enabled true

# 設定自己為 Worker
openclaw config set nodes.role worker

# 連線到主控節點
openclaw nodes join --primary https://你的主控域名:18789 --key sk-nodes-xxxxxxxxxxxxxxxx
```

連線成功的畫面：

```
✅ 已成功連線到主控節點！
   主控：https://lobster.你的域名.com:18789
   我的節點 ID：node-def456
   我的角色：Worker
   延遲：32ms
```

### 19.3.4 步驟三：建立 NODE.md

在工作節點的工作區裡建立 `NODE.md`，宣告這個節點的能力：

```markdown
## 節點名稱
辦公室筆電

## 能力
- file-access（可存取辦公室的共享資料夾）
- browser（可操控瀏覽器）
- office-tools（有裝 Office 軟體）

## 在線時段
- 平日：09:00-18:00
```

### 19.3.5 步驟四：測試連線

回到主控節點，確認工作節點已經上線：

```powershell
openclaw nodes list
```

輸出範例：

```
🌐 Nodes 網路狀態：

  [Primary] node-abc123 — 雲端伺服器
    狀態：✅ 在線
    IP：xxx.xxx.xxx.xxx
    運行時間：3 天 2 小時

  [Worker] node-def456 — 辦公室筆電
    狀態：✅ 在線
    延遲：32ms
    能力：file-access, browser, office-tools
    在線時段：平日 09:00-18:00
```

### 19.3.6 步驟五：測試分派任務

用 LINE 傳一個需要工作節點才能做的任務：

```
你（LINE）：幫我看看辦公室電腦桌面上有什麼檔案
龍蝦：📡 分派任務到「辦公室筆電」...
      📁 辦公室筆電桌面上的檔案：
      - 會議簡報.pptx
      - 本月報表.xlsx
      - 專案進度.docx
      共 3 個檔案。
```

龍蝦會在回覆裡標示任務是由哪個節點執行的，讓你知道「這件事是哪台電腦做的」。

## 19.4 實戰範例

### 19.4.1 範例一：家庭 + 雲端雙節點

這是最常見的設定——雲端伺服器當主控（24 小時在線），家裡桌機當工作節點（有 GPU、有檔案）。

**架構：**

| 節點 | 角色 | 位置 | 負責什麼 |
|------|------|------|---------|
| GitHub Codespaces | Primary | 雲端 | 接收 LINE 訊息、基本對話 |
| 家裡桌機 | Worker | 家裡 | AI 運算、瀏覽器操控、檔案管理 |

**使用情境：**

```
場景：你在外面用手機

你（LINE）：今天天氣如何？
龍蝦：☀️ 台北 28°C，晴天。（由雲端節點回答）

你（LINE）：幫我看看家裡電腦桌面上那份報告的內容
龍蝦：📡 分派到「家裡桌機」...
      📄 report.docx 摘要：
      ...（內容摘要）
```

簡單的聊天由雲端節點處理（因為它 24 小時在線），需要操控桌面的任務則分派給家裡桌機。

### 19.4.2 範例二：辦公室 + 家裡雙向管理

如果你有辦公室電腦和家裡電腦，可以讓龍蝦同時管理兩邊：

```
你（LINE）：辦公室電腦上的專案進度更新到哪了？
龍蝦：📡 詢問「辦公室筆電」...
      📋 專案進度（截至今天 15:00）：
      - 前端開發：75%
      - 後端 API：90%
      - 測試：40%

你（LINE）：把那份進度報表也複製到家裡電腦的桌面
龍蝦：📡 從「辦公室筆電」下載...
      📡 上傳到「家裡桌機」...
      ✅ 已複製到家裡桌機的桌面。
```

### 19.4.3 範例三：多人共用龍蝦網路

如果你和朋友各自有一台跑龍蝦的電腦，也可以組成一個 Nodes 網路，讓龍蝦互相協作：

```
場景：你是專案經理，朋友 A 是設計師，朋友 B 是工程師

你（LINE）：幫我問 A 的龍蝦，設計稿完成了嗎？
龍蝦：📡 詢問「A 的工作站」...
      🎨 A 的龍蝦回報：首頁設計稿已完成，
      共 5 個頁面，放在共享資料夾裡了。

你（LINE）：好，把設計稿轉給 B 的龍蝦，請它開始切版
龍蝦：📡 轉派任務到「B 的工作站」...
      💻 B 的龍蝦回報：收到設計稿，開始切版。
      預計完成時間：明天下午。
```

> 💡 這種「龍蝦對龍蝦」的協作目前還在早期階段，實際使用時可能需要較多的手動設定。但概念本身非常有潛力——想像未來每個人都有自己的 AI 助手，AI 助手之間可以互相溝通協作。

## 19.5 Nodes 的注意事項

### 19.5.1 網路與安全

| 項目 | 說明 |
|------|------|
| **連線加密** | 節點之間的通訊使用 TLS 加密，不用擔心被竊聽 |
| **金鑰管理** | 連線金鑰只在 `nodes join` 時使用一次，之後用節點 ID 認證 |
| **防火牆** | 工作節點不需要開放 Port，它是主動連出去的 |
| **斷線重連** | 工作節點斷線後會自動嘗試重連（間隔 30 秒） |

### 19.5.2 效能考量

- 節點之間的延遲會影響回覆速度——如果工作節點在海外，回覆會比較慢
- 大檔案傳輸（例如跨節點複製影片檔）可能需要較長時間
- 建議同一區域（例如都在台灣）的節點互連，延遲會比較低

### 19.5.3 目前的限制

Nodes 是 OpenClaw 比較新的功能，目前有一些限制：

- 最多支援 5 個工作節點
- 跨節點的檔案傳輸有大小限制（預設 100MB）
- 工作節點不能直接回覆使用者，必須透過主控節點
- 節點之間的任務分派邏輯還比較基礎，不像企業級的任務佇列

## 19.6 常見問題

**Q1：一定要有雲端伺服器才能用 Nodes 嗎？**

不一定。如果你的兩台電腦在同一個區域網路裡（例如都在家裡的 Wi-Fi），可以直接用區網 IP 連線，不需要雲端。但如果兩台電腦不在同一個網路，就需要 Cloudflare Tunnel 或其他方式讓它們能互相連線。

**Q2：工作節點關機了會怎樣？**

主控節點會偵測到工作節點離線。如果有任務需要那個節點的能力，龍蝦會告訴你「該節點目前離線」。等節點重新開機並連線後，會自動恢復。

**Q3：GitHub Codespaces 可以當主控節點嗎？**

可以，而且是很好的選擇——免費 120 小時/月，24 小時在線（在使用時段內）。但要注意 Codespaces 超過 30 分鐘沒有活動會自動休眠，你可能需要設定 keep-alive。

**Q4：Nodes 和 CH14 的多重分身有什麼不同？**

CH14 的多重分身是「一台電腦上跑多個龍蝦 Gateway」——多個獨立的龍蝦。Nodes 是「多台電腦上的龍蝦串在一起」——一個龍蝦網路，互相合作。兩者可以搭配使用。

**Q5：節點之間的通訊安全嗎？**

安全。所有通訊都經過 TLS 加密，而且需要金鑰認證。未經授權的機器無法加入你的 Nodes 網路。

## 19.7 小結與展望

這一章介紹了 OpenClaw 的多機協作能力：

- **Nodes 架構**——Primary 主控 + 多個 Worker 工作節點
- **節點設定**——`openclaw nodes init` 初始化 + `openclaw nodes join` 加入
- **能力宣告**——NODE.md 定義每個節點能做什麼
- **實戰範例**——家庭+雲端、辦公室+家裡、多人協作

當你的龍蝦網路建起來之後，它就不再是一隻「住在一台電腦裡的 AI」，而是一個「分散在多台機器上的 AI 系統」。

但龍蝦跟你的互動方式一直都是文字——你打字，它回文字。有沒有可能用「說的」？不是語音辨識轉文字那種，而是真的打電話跟龍蝦聊天？在下一章 CH20，我們要教你用 **Twilio 語音通話**功能，讓你可以真的「打電話給龍蝦」。
